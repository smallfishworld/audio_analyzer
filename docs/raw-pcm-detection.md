# RAW PCM 智能推断与人工修正

> 目标：在不捏造采样率、声道等元信息的前提下，提高裸 PCM 导入效率。

## 交互

打开 `.pcm` / `.raw` / `.bin` 后，软件会自动读取有限大小的样本（目前最多 128 KiB）尝试推断音频编码，将建议值**填写到可编辑的导入表单**，而不是立即开始全文件测量。用户可以检查、修改和确认，然后点击 Analyze PCM。可随时点击 Re-detect 重新判断，或点击候选解释切换格式/端序。

标记为 **Filename clues（文件名线索）**、**Statistical estimate（统计估计）** 或 **Format uncertain（格式不确定）**；同时单独展示可能推断到的字段和采用默认设置的字段，不将猜测标记为确凿事实。

## 可利用的信息

| 参数 | 自动检测依据 | 限制 |
|---|---|---|
| Sample format（u8/s8/s16/s24/s32/f32/f64） | 文件名如 `s16le` / `f32be` / `16bit`；有限数据的数值连续性、振幅范围等评分 | 只能推测，静音、随机噪声、某些采样格式间不可靠 |
| Byte order（little/big） | `le` / `be` 文件名；数据解释评分 | 在整数字节值相似或低动态信号中可能无法区分 |
| Sample rate | 仅接受明确的 `sr32000`、`fs48000`、`rate96000`、`samplerate_48000` 等文件名标记 | PCM 字节不带采样率；文件名 `test_4khz` 可能表示信号频率，因此**不当作采样率** |
| Channels | `mono`、`stereo`、`2ch` 等文件名；否则优先上次导入参数 | 多声道 PCM 原始字节不能可靠判断声道数 |
| Layout | 文件名 `planar` 或 `interleaved`，否则保留上次选择 | 不能安全地完全自动判断 |
| Header offset | 保留上次值（不大于文件长度），否则为 0 | 裸数据没有可核验的头大小 |

检测执行在后台 Rust 工作线程，**不会读取整个 PCM 文件**，不会修改原始文件；手动确认后仍使用已实现的全文件流式 RMS/Peak/波形统计。上次手动选择的设置本地保存，下次作为待核对默认值使用。

## 测试重点

- 明确的 `sr32000_s16le_stereo_interleaved` 文件名与格式、声道、采样率正确识别。
- `test_4khz_0dbfs` 的 `4kHz` 不会错误判断成音频采样率。
- 无信息的全静音文件不应“自信”识别为某种格式，并保留用户上次参数。
- f32 正弦信号可以作为候选解释出现。
- 不可信格式仍允许用户自由设置采样率、端序、布局、位深、头偏移后继续分析。

这是**推测辅助**而非标准化 PCM 媒体探测；当用户知道采集端配置时，采集端参数优先于任何自动推断。
