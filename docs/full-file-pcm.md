# 完整 PCM/WAV 文件分析（分块扫描）

> 目标：去除 M0/M1 对裸 PCM 与标准 PCM WAV 的 3 秒预览限制。此文档描述新功能分支；旧 v0.2.0-alpha.1 安装包仍受 3 秒限制。

## 功能语义

| 指标 | 新的 RAW/WAV 行为 |
|---|---|
| 全文件 Sample Peak（dBFS） | 读取被选声道的每一帧，精确取最大绝对值 |
| 全文件 RMS（dBFS） | 对被选声道每一帧累积平方和，最后计算均方根 |
| 波形概览 | 覆盖全文件，按时间区间取 min/max，最多约 1200 组输出 |
| FFT 和主频 | 使用可指定起始时间的 4096 帧 Hann FFT；**不声称是全文件 FFT** |
| 元数据 / 时长 | 使用实际 PCM 采样率、声道数及完整帧数计算 |
| 内存 | 输入使用 8192 帧定长缓冲，波形约 1200 组，FFT 缓冲 4096 帧，不将整份原始数据加载内存 |
| 多声道 | 一次分析用户选择的单个通道；interleaved/planar 都支持 |
| 旧格式预览 | MP3、AAC、FLAC、Opus 等 FFmpeg 路径仍只处理前三秒 |

## PCM 输入

支持 u8、s8、s16、s24、s32、f32、f64；可指定小端/大端、header offset、声道数（1~16）和 interleaved/planar。处理时使用指定的格式解释原始字节；PCM 文件本身不包含采样率或位深等元数据。

对于很大的 PCM，程序需要实际遍历所有采样点才能精确得到全文件 Peak 和 RMS，因此**耗时仍与文件大小近似成正比**。当前在后台 Rust 线程执行，界面呈现分析中状态，但尚未提供扫描进度条、取消、全文件索引缓存或快速重算选区。

## FFT 的正确用法

输入 FFT 起点（单位秒），单击 Update FFT。FFT 取该位置的 4096 个连续采样帧。若起点过于靠近结尾，则向前钳制，确保有足够样本；短于 4096 帧时不产生完整 FFT。修改 FFT 时间或声道会重新扫描全文件，属于初版行为，后续优化为随机读取 FFT 窗口而无需重复计算全文件指标。

**全文件 Peak/RMS 和 FFT 的统计窗口不同，不能把单个 4096 点 FFT 解释为整段音频的频谱。** 未来可增加 Welch PSD/STFT、频率随时间演变以及按选区统计。

## 新增自动化测试

- 5 秒 PCM：前 4 秒静音，第 5 秒 1 kHz，验证尾部数据参与全文件 RMS/Peak、波形和时间定位 FFT。
- 5 秒 planar 双声道：CH1 静音、CH2 后一秒满幅，验证跨通道选择和尾部能量。
- 4 秒 WAV：验证前 3 秒外的样本计入全文件 RMS 和 Peak。
- 8 MiB 稀疏 PCM：验证全部帧被处理且仅返回受限数量的波形点。
- 原有 24bit 端序、浮点 dBFS、高频 47 kHz、八种编解码器回归均应保持通过。
